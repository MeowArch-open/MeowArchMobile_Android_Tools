# MeowArchMobile_Android_Tools

[![build](https://github.com/MeowArch-open/MeowArchMobile_Android_Tools/actions/workflows/build.yml/badge.svg)](https://github.com/MeowArch-open/MeowArchMobile_Android_Tools/actions/workflows/build.yml)

AOSP's mobile tooling rebuilt standalone from upstream sources — no Android
userland, no soong:

* [`adbd-standalone/`](adbd-standalone/) — AOSP's **adbd** as a native glibc
  binary for **Arch Linux ARM (aarch64)**: TCP adb plus USB (FunctionFS).
  Runs *on* the device.
* [`adb-standalone/`](adb-standalone/) — AOSP's host **adb** client
  (platform-tools' `adb`), built standalone for **x86_64 Linux**: real USB via
  libusb, TCP/`adb connect`, shell/sync/forward/pairing with brotli/lz4/zstd
  compression. Runs on the host, talks to real phones.
* [`better_fastboot/`](better_fastboot/) — AOSP's official host **fastboot**
  tool for **x86_64 Linux** (real `usb_linux` backend, Android-forked
  `mke2fs`/`make_f2fs` for `fastboot -w`) **and Windows** (`fastboot.exe`,
  mingw-w64 i686 cross-built exactly like Google's, `usb_windows.cpp` +
  AdbWinApi). Runs on the host, talks to real phones. Plus UX additions:
  live progress bar with speed/ETA, Did-you-want typo suggestions, colors,
  four languages (en/zh_CN/zh_TW/ja), generated bash/zsh/fish completions, and
  `flash-x` — flash a partition straight out of an OTA `payload.bin` without
  unpacking it first.

All three compile the genuine AOSP sources in place from a shared partial checkout
(`../aosp-adbd`, pinned SHAs — see each README's Upstream table).

## Quick start

On the device (adbd):

    pacman -U adbd-meowarch-*.pkg.tar.zst
    sudo systemctl enable --now adbd
    adb connect <device>:5555

On the host (adb):

    pacman -U adb-meowarch-*.pkg.tar.zst
    adb-meowarch devices
    adb-meowarch -s <serial> shell

On the host (fastboot):

    pacman -U fastboot-meowarch-*.pkg.tar.zst
    fastboot-m devices
    fastboot-m flash boot boot.img
    fastboot-m flash-x boot payload.bin      # straight from an OTA payload

(`fastboot-meowarch` is installed as an alias; the distro's `android-tools`
`fastboot` is untouched, so both packages coexist.)

## Build

adbd (x86_64 + aarch64 cross):

    cd adbd-standalone
    ./scripts/fetch-aosp.sh         # pinned partial AOSP sources (~300 MB)
    cmake -B build-native && cmake --build build-native -j$(nproc)
    ./scripts/make-sysroot.sh       # ALARM cross sysroot
    cmake -B build-aarch64 -DCMAKE_TOOLCHAIN_FILE=cmake/aarch64.cmake \
          -DHOST_PROTOC=$PWD/build-native/protobuf/protoc
    cmake --build build-aarch64 -j$(nproc)
    CARCH=aarch64 makepkg -f

adb (x86_64 Linux):

    cd adb-standalone
    ./scripts/fetch-aosp.sh         # shares ../aosp-adbd
    cmake -B build-native -G Ninja -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
    cmake --build build-native -j$(nproc)
    makepkg -f
    bash scripts/test-adb.sh        # end-to-end against adbd-standalone

fastboot (x86_64 Linux):

    cd better_fastboot
    ./scripts/fetch-aosp.sh         # shares ../aosp-adbd with adbd-standalone
    cmake -B build-native -G Ninja && cmake --build build-native -j$(nproc)
    makepkg -f

fastboot.exe (Windows, mingw-w64 cross — needs `mingw-w64-gcc`):

    cd better_fastboot
    cmake -B build-win32 -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-i686.cmake
    cmake --build build-win32
    # build-win32/: fastboot.exe + AdbWinApi.dll + AdbWinUsbApi.dll (ship together)

Shell completions are generated by the binary itself and packaged for
bash/zsh/fish under both command names; regenerate manually with
`fastboot-m --shell-completion=bash|zsh|fish` (see better_fastboot/README.md).

CI builds and smoke-tests all of it on every push (Linux native + aarch64
cross + fastboot.exe on a real Windows runner).
